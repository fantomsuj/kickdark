# Dark-theme evidence and testing

Kick Night Mode tests its production stylesheet against sanitized structures
captured from authenticated Kick routes. The repository never needs the raw DOM,
page copy, form values, URLs, account identifiers, or authenticated screenshots.

## Install the browser

Use Node.js 20 or newer, install the exact locked dependencies, and install the
Playwright Chromium build:

```bash
npm install
npx playwright install chromium
```

The Playwright configuration uses its bundled `chromium` channel. Keep
`@playwright/test` pinned to the exact version in `package.json` and
`package-lock.json`; update the dependency and reviewed snapshots together.

## Test commands

```bash
npm run test:unit
npm run test:visual
npm test
npm run check
```

- `test:unit` runs unconditional activation, manifest, privacy, palette,
  selector, print, and media-protection contracts.
- `test:visual` renders every sanitized fixture with the production stylesheet,
  audits computed contrast and interaction states, and compares reviewed
  screenshots.
- `npm test` runs both suites.
- `check` runs both suites and the packaged-extension validator.

The computed-style audit composites transparent ancestor backgrounds before
measuring contrast. Normal text must reach 4.5:1. Large text, controls, borders,
and focus indicators must reach 3:1. The state suite covers default, hover,
selected, expanded, disabled, focus-visible, menu, dialog, form, and empty-state
surfaces. A rendered print test confirms that dark-theme specificity cannot beat
the light print reset.

## Fixture refresh

Authenticated captures are temporary inputs and belong only under
`.context/captures/`. Never copy a browser snapshot, raw `outerHTML`, page text,
input value, URL, ID, inline style, accounting value, or real screenshot into the
repository or an agent response.

1. Open the authenticated Tasks, Documents, Transactions, Clients, Accounts,
   Rules, Profit & Loss, Invoicing, and Billing routes in Chrome. Also exercise
   the New Task drawer, a filter dialog, menu, form, empty state, and training
   banner.
2. Load `scripts/sanitize-kick-dom.js` into the page and invoke the sanitizer
   inside the page context. Sanitize before serialization; do not retrieve raw DOM
   and sanitize it afterward.
3. Save only the sanitizer result as JSON beneath `.context/captures/`. Confirm
   that it contains tags, allowlisted stable class tokens, roles, and necessary
   ARIA/state attributes, with synthetic text markers in place of all copy.
4. Rebuild tracked fixtures and the selector inventory:

   ```bash
   npm run fixtures:build
   ```

5. Review the generated HTML and inventory diff. Run the privacy, selector, and
   contrast tests before refreshing images.
6. Update and visually review sanitized snapshots:

   ```bash
   npm run test:visual -- --update-snapshots
   npm run test:visual
   ```

7. Keep authenticated screenshots, if a human QA pass requires them, under
   `.context/` only. Do not stage or commit them.

The generator rejects unsafe capture data before it writes a tracked fixture.
The privacy suite independently checks the sanitizer and generated fixture set.

## Selector inventory rules

`test/fixtures/selector-inventory.json` is generated by matching production
selectors against the combined captured fixtures. Each production page-theme
selector must match at least one captured route. The only documented exceptions
are the dark root, application roots, print selectors, scrollbar pseudo-elements,
and protected-media selectors.

Production selectors may use stable element names, roles, ARIA/state attributes,
and class tokens retained by the sanitizer. Do not use:

- CSS-module hashes or other generated class tokens
- broad class or inline-style fragments such as `[class*="..."]` or
  `[style*="..."]`
- hypothetical `data-slot` or `data-variant` hooks absent from the inventory
- fixture-only `data-kick-night-test-*` attributes
- `filter: invert(...)`

Adopt a Kick custom property only when authenticated CSSOM evidence shows that it
controls the same semantic surface on at least two captured routes and does not
alter protected media or financial-state styling. The current inventory records
`--border-color` only for verified header and table-group borders on Tasks,
Documents, and Transactions. Other theme gaps use exact captured selectors.

## Authenticated release QA

After `npm run check` passes, reload the unpacked extension and use an
authenticated Kick tab without saving page content:

1. Confirm the dark root is present immediately after reload on Tasks,
   Transactions, Clients, Documents, Accounts, Rules, Profit & Loss, Invoicing,
   and Billing.
2. Exercise filters, menus, the New Task drawer, disabled calendar periods,
   selected rows, horizontal tables, empty states, and the training banner.
3. Verify all ordinary navigation links are neutral and content actions retain
   blue emphasis.
4. Navigate with the keyboard and verify a visible, high-contrast focus ring.
5. Open print preview and confirm the document is light with dark text; cancel
   without printing.
6. Confirm there are no white glare bands, unreadable totals, layout changes,
   or console errors at desktop and compact widths.

Do not persist authenticated DOM, screenshots, text, URLs, or form values during
this pass.
